# Changelog

## 2026-08-02 (Living catalog engine)
- **Live catalog + freshness check:** `researchBrand()` in `src/lib/research.ts` restructured from a gummy-only schema to a unified `productCatalog` that classifies every product by `type` (gummy|oil|topical|capsule|patch|flower|other) AND `status` (available|coming_soon|sold_out), then partitions into `gummyProducts` / `otherProducts` / `comingSoon`. One engine now produces four honest outcomes instead of silently returning nothing.
- **Four research outcomes:** `/api/research` returns a `status` field (`new_brand_no_gummies` | `new_brand_added` | `existing_brand_refreshed` | `existing_brand_unchanged` | `cached`) that the client renders distinctly. New brand with no gummies (e.g. Sanan Relief — topicals only) → honest decline card instead of a fabricated gummy. Existing brand with a newly-shipped SKU (e.g. Moon Impact DRIFT/GROUND CONTROL going live) → additive refresh.
- **Additive-only refresh:** `forceRefresh` bypasses the 7-day cache. Existing-brand refresh NEVER deletes or overwrites seeded products — it computes a name-delta and inserts only genuinely-new gummies, protecting the 12 hand-curated brand seeds.
- **Footer-aware licence scrape:** `gatherContext()` now fetches `/contact`, `/about`, privacy/terms and emits a `LICENCE EXTRACT` block via literal-string grep for `Licence Number:` (see `tasks/lessons.md` §5). Kills the licence-in-image mistake — the agent copies footer text verbatim rather than inferring from a badge. Also captures availability signals (`coming soon`, `sold out`) for the freshness check.
- **Frontend cards:** `src/app/app/chat-client.tsx` adds a `research_status` message kind + `ResearchStatusCard` (decline + freshness), a "Just added N" refresh badge on refreshed dashboards, and a "Find me a gummy instead" CTA that re-enters the match flow.
- **Agent prompt:** `src/lib/saul-agent.ts` `researchBrand` tool now described as research-or-freshness-check for ANY brand; system prompt frames the catalog as a living snapshot and steers non-gummy brands toward a real match.
- **Lazy OpenAI client:** `research.ts` creates the OpenAI client at call-time instead of import-time (matches the Senso pattern). Fixes a dotenv-hoisting bug that silently fell back to mock in tsx scripts (the static import ran before `dotenv.config()`).
- **Verified live:** `scripts/test-live-research.ts` (gitignored) confirms Sanan Relief → `sells_gummies:false` with 5 oils/topicals, and Moon Impact → DRIFT/GROUND CONTROL tracked as `coming_soon`.

Previously the live path produced brands with no support email (→ broken `support@<domain>` guess) and no Senso doc (→ ungrounded recommendations).
